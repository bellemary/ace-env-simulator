# v1.3 解码证据与后续所需数据

## 已验证的静态变换

- `sub_237E08` 调用 `sub_4E9A50(30548)`，以固定索引从 `libtersafe.so` 内部混淆常量区恢复 36 字节循环 XOR 序列。该输入不来自会话、账号或服务端响应。
- `ano_rdp.dat`：固定魔数 `0x20220920`、长度和 36 字节循环 XOR；当前输出是 32 字节十六进制摘要。
- `crt.i2.dat`：`sub_4D9214` 写入，`sub_4D949C` 读取；固定魔数 `0x20220606`、CRC32、分组记录和固定字符串变换。
- `ano_ksh.dat`：`sub_4D1EE8` 读取；固定魔数 `0x20230407`、字符串变换、三个 LE32 字段、CRC32 和尾魔数。
- `mrpcs_a_v.data`：ZIP 内层从偏移 4 起 XOR `0x4F`，首四字节为解码后数据的 LE32 CRC32。
- `mrpcs_a_v_f.data`：ZIP 内层从偏移 4 起 XOR `0x84`，采用同一 CRC 边界。
- `a64.dat`：固定 256 字节查表，`body[i] = table[cipher[i] XOR 0x23]`。

上述文件无需目标进程保持运行。目标进程是否处于大厅或对局，只影响文件有没有生成、有没有刷新以及是否存在尚未落盘的最终上报缓冲区。

## 当前不能解释为密钥失败的项目

- `mrpcs_a.data`、`mrpcs_a_c.data`：外层 ZIP 已提取，内层算法未闭合，禁止套用 `0x4F/0x84`。
- `comm.dat`：已确认是运行时配置容器，目前只报告经过二进制规则验证的键名，尚未恢复完整键值编码。
- `ano_rdp_2.dat`、`atti_obv.dat`、`kmc.dat`、`kvcache8.dat`、`cache_crc.dat`、`cpcah.dat` 等：缺少经过生产者/消费者和完整性校验共同验证的格式规格。
- `ms_*_tmp.dat`：本次报告中大部分长度为零，不存在可解码载荷。
- Root、BL、证书有效性、设备密钥有效性和坐标状态的最终事件字段：尚未在已解析持久文件中定位。

## 下一轮必须提供的动态与对照数据

每份采集都必须保留原始文件、文件路径、长度、修改时间、SHA-256、游戏版本、`libtersafe.so` SHA-256 和采集时间点。

1. 当前 v1.2/v1.3 高级模式导出的 `高级Ace检测文件解密报告_*_解密源文件.zip`。只有 TXT 报告不足以恢复新格式。
2. 同一设备、同一游戏版本的三阶段完整 ZIP：目标进程关闭、大厅稳定 30 秒、对局稳定 30 秒。
3. 同版本的两类对照：BL 锁定且无 Root；BL 解锁或已知 Root。除被测变量外尽量保持系统版本和客户端版本一致。
4. 三阶段仍无最终事件字段时，记录 `TssSDKGetReportData`、`TssSDKGetReportData4` 每次成功返回的原始缓冲区、实际长度、调用时间、调用线程、对应阶段和同刻 `ano_tmp` 快照。
5. 若返回缓冲区继续引用二级数据，再记录 `TssSDKOnRecvData` 的输入原文和长度，用于区分本地事件编码与服务端下发配置。
6. `files/key`、`files/serial`、`files/.Save` 若存在，必须连同路径、长度、修改时间和原始副本一起采集；不存在也要保留 `find/stat` 结果。

在获得上述对照之前，应用将未闭合字段显示为风险待排查，不把规则能力字符串、文件存在、CRC 通过或本应用的 Root 权限当作设备已被 ACE 上报的证据。
